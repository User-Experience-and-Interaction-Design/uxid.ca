Which venue for which area

Built from the area tags in the workbook. The first line is where the workbook marks that area a core topic (gold is Tier 1). Generalist venues like CHI, DIS and UIST are tagged as partial on nearly every area rather than core, so the Tier 1 venues that also cover it are listed underneath.

AreaVenues that treat it as a core topic

Source: in your iCloud Conference Deadlines folder. The page is generated from that workbook, so the spreadsheet stays the one place you edit; re-export and the page follows. One exception: on 23 October 2026 every conference's next-event location was checked against its official site and 17 entries were corrected in the page's data file only (for example AIED 2027 is in Adelaide, not Huntington Beach). Copy those into the workbook before the next export, or it will undo them.

Fit is computed, not from the workbook. Your Fit_Score column is empty, so the page derives it: the area tags the workbook gives each venue, weighted towards the lab's own topics (smartwatch 1.0, mobile 0.8, human-AI 0.8, visualization 0.6, accessibility 0.5; a “partial” tag counts half), plus the HCI relevance rating, all multiplied by a tier factor so a weak venue tagged across many areas cannot outrank a strong one. The result is scaled so the closest-fitting venue in the list scores 5 — 5 means best fit here, not perfect fit. Fill in Fit_Score in the spreadsheet and the page will use your number instead.

Attendance comes from the workbook's presentation mode. “In person*” means in person with remote allowed only by exception; the exact wording is in the expanded row. Pages, acceptance and CORE notes are shortened in the table and shown in full there too.

Highlights. Venue names on a solid gold label are the lab's main venues; a gold A* is a CORE A* conference. The next-event location is coloured by continent (see the legend above the table), and the Continent filter uses the same locations. Locations still marked TBA are left uncoloured and count as “not announced yet”, even when the workbook guesses a region.

On the passcode: it is checked in the browser against a hash, so the passcode itself is not in the page source, but the data file sits at a plain URL beside the page. It keeps this out of casual sight and out of search results; it is not real access control.

Not every row is dated. Rolling journals show Rolling and tracks whose call is not out yet show not announced; both stay visible under “upcoming only”. Venues the workbook marks discontinued are left out.
